# Actor Batch Arena

The Web64 v2 Game Runtime example for the open actor-batch pipeline.

The project keeps 32 actors in caller-owned SoA storage and exposes every intermediate stage to C and assembly. Eighteen actors form the visible hot cohort, four use native two-layer overlay commands, and the PAL mux owns only VIC slots 2–7 while a direct HUD pair remains fixed in slots 0–1. An application-owned 32-sample sine/velocity adapter integrates every actor's Q12.4 X position and updates the public visible bounds. Base and overlay frame indices advance independently.

The project starts at `$4000`, keeping the complete linked image below the BASIC-ROM window and leaving the application-owned IRQ wrapper visible under the KERNAL dispatcher’s normal `$37` memory map. It enters through `SEI`; interrupts remain disabled throughout initialization and first-schedule construction so KERNAL IRQ work cannot borrow the compiler/runtime zero page. The application wrapper enables interrupts with `CLI` only after it owns the vector. These memory-map and interrupt choices are explicit application policy rather than hidden runtime side effects.

Each application-owned frame begins the inactive mux buffer, updates open motion/animation inputs, runs the fused actor-to-mux adapter, commits the prepared schedule, and advances the next caller-owned animation state. The adapter consumes explicitly proven stable bounds, precomputed pair output, stable topology/order, and preintegrated motion; the same visible, pair, command, and mux buffers remain inspectable and replaceable from C or assembly. Four pairs deliberately share one vertical band, creating repeatable priority pressure against six owned slots. Pairs are submitted as one logical command and can never separate. The IRQ wrapper acknowledges the VIC source, advances the game tick only at the mux frame boundary, calls the fast service inside the KERNAL register envelope, and owns chaining/RTI.

`WEB64_EXAMPLE_VERIFY` runs 120 synthetic PAL frames and publishes `verification_complete`, `frame_counter`, `verification_pair_frames`, `verification_independent_frames`, `verification_motion_changes`, and `verification_stable_drop` for automated inspection. The release verifier also runs 120 consecutive frames in the PAL emulator and asserts that all 18 visible actors move, no `begin_frame` call is busy, every overlay precedes its base, reserved HUD bytes stay unchanged, reuse events remain safe, and the stable result stays at 9 accepted logical entries/13 accepted layers with 9 dropped entries/9 dropped layers. The measured application frame is 12,487 PAL cycles. Normal builds install the application IRQ and run continuously.

This is a standalone `web64-examples` project; its open-buffer pipeline is also the basis of the Web64 v2 Actor Batch Arena runtime example.
